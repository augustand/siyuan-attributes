# 按库查询（9-21 设计里被转向吸收掉的第一刀）

**日期：** 2026-09-29
**状态：** 草稿（待对话确认）
**前置：** 类型分组管理台已交付；`listDatabaseBoundDocs` 服务与测试已在
**来源：** 2026-09-21 文档数据库管理器设计「查询（薄）」一节；9-23 业务类型转向时未吸收

## 问题

Dock「我们的库」的「文档」对话框是平铺的绑定文档列表，无任何筛选。库文档一多，「找一个文档」只能肉眼扫。9-21 第一刀设计的「按列 equals/contains/isEmpty 筛选 + 结果跳转文档」是三个目标里唯一没被后续任何一刀实现的。

## 目标（薄刀：客户端过滤）

1. 「文档」对话框内升级为可筛选列表：
   - **选列**：来自该库真实 AV 列（按 `avID` 取列定义：`renderAttributeView` / `getAttributeView` 内核接口之一，实现时定型并封装进 service），显示列名与类型
   - **条件**：`equals` | `contains` | `isEmpty`；按列类型给对应控件（文本→输入框；单/多选→选项选择；数字→输入框；日期→日期文本）
   - **结果**：对当前绑定文档列表客户端过滤，显示命中数
   - **点击结果** → 打开文档
2. 筛选仅存在于对话框内，不持久化（无保存视图、无跨库查询）
3. 绑定文档多的库也可用（首版不做分页，但命中数可见）

## 非目标

- 内核侧查询 / SQL / 索引
- 保存视图、多条件与或组合、跨库联合查询
- Dock 上独立「查询」页签（仅对话框内）
- 自动绑定 / 路径规则（P2+ 另议）

## 要点

- `src/views/DocDatabaseDock.vue`：「文档」对话框加列选择 + 条件控件 + 客户端过滤
- 值比较走纯函数（新建 `src/services/databaseQuery.ts`）：`matchDoc(doc, column, condition, value)`，单测覆盖
- AV 值形状异构（单/多选、日期）在模型层归一化，沿用既有 normalize 约定
- i18n 键按第 5 刀建立的规范补齐（本刀只消费，不新增机制）

## 成功标准

1. 某库文档对话框按文本列「包含」筛选出子集并点开文档
2. 「为空」能找出未填列的文档
3. 命中数正确显示；清空条件恢复全量
4. `matchDoc` 单测覆盖 equals / contains / isEmpty × 文本 / 选项 / 日期

## 留给实现计划的开放点

- AV 日期 / 多选列值的精确形状，对照当前内核在实现时拍板
- 绑定文档量级极大时是否分页——先上命中数，卡了再加
