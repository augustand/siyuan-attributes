# 库列表管理：过滤 / 只看异常 / 行内改名 / 补齐列

**日期：** 2026-09-29
**状态：** 草稿（待对话确认）
**来源：** 2026-09-29 差距盘点（管理层）

## 问题

1. 库一多，「我们的库」只能滚动找：无关键字过滤、无「只看异常」
2. 改名入口只在设置页，Dock 看不到名字编辑；两个管理面已经出现文案漂移
3. 早期建库或列被手动删过的库缺模板列，没有手动修复入口——只能靠再挂一次文档顺带补（挂接/归类路径会自动补，已核实）

## 目标

1. Dock「我们的库」标题行加关键字过滤（匹配库名 + 类型标签）；空关键字即全量
2. 「只看异常」开关：存在异常库才显示
3. 行内改名：点库名进入编辑，写 `OwnedDatabase.name`（复用设置页同一字段，不加字段）
4. 行操作「补齐列」：`ensureOwnedDatabaseTemplateColumns`（已在，返回 `{ added }`）；成功 toast「已补 N 列」，无缺列提示「列已齐全」
5. 设置页同步：补齐列按钮必加，过滤可选——两处共用同一动作函数

## 非目标

- 排序 / 批量操作 / 各类型文档数概览（下一刀）
- 更换库类型（P2，单独刀）
- 修复异常库本身（既有非目标：只从名单移除，不删 AV 文件）
- 死代码清理（休眠规则机制，单独刀）

## 要点

- 过滤为纯函数 `filterOwnedDatabases(databases, { keyword, brokenOnly })` + 单测
- 复用现有健康图（挂载/事件后已刷新，不重复请求）
- 改名走与设置页同一写入路径（emit settings-changed，Dock/归类即时感知）
- 补齐列幂等（服务已按列名去重）

## 成功标准

1. 关键字即时缩小列表，清空恢复；「只看异常」无异常时入口隐藏
2. Dock 行内改名后，设置页/文档树归类立即用新名
3. 缺列库点「补齐列」得「已补 N 列」；齐全库提示「列已齐全」
4. 纯函数单测覆盖 keyword × brokenOnly 组合；现有测试不回归
