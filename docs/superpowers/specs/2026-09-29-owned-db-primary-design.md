# 显式「设为主库」（每类型一个主库）

**日期：** 2026-09-29
**状态：** 草稿（待对话确认）
**前置：** 文档树归类 + 类型分组管理台已交付
**来源：** 2026-09-29 差距盘点（管理层）；2026-09-23 文档树归类设计遗留项

## 问题

同类型多库时，主库靠「挂接即记为主库」隐式产生：不可发现、不可控——想把主库换成非最近使用的那个，只能再挂一篇文档。归类设计的非目标清单里明确把显式按钮留作后续，至今未做。

## 目标

1. 「我们的库」分组行（健康库 ≥2 的类型）提供「设为主库」；当前主库显示徽标
2. 写入现有 `ownedDbPrimaryByType` 字段（normalize 已在 `settings.ts`），不加新字段、不迁移
3. 支持「清除主库」→ 回退「最近使用」语义
4. 类型仅一个健康库时不显示动作（它已经是主库）
5. 挂接仍是显式动作：用户再挂接 = 再次改主库（保留现有语义，本刀不改）

## 非目标

- `ownedDbPrimaryByType` 结构调整
- 跨类型主库 / 多主库
- 改思源原生「添加到数据库」菜单
- 归类服务语义变化（挂接覆盖显式主库，保持现状）

## 要点

- `src/views/DocDatabaseDock.vue`：分组行操作区加「设为主库 / 清除主库」；主库行加徽标
- `src/views/SettingContent.vue`：同一操作同步，避免两个管理面漂移
- 主库解析顺序保持现有实现（显式主库 → 最近使用 → 唯一健康 → 第一个），本刀只加写入入口
- i18n 键按 `ownedDb.*` 惯例新增，两份语言包同步落（缺键补齐见第 5 刀 spec）

## 成功标准

1. 同类型 2+ 库：手动把非最近使用的设为主库，文档树右键「标为该类型」挂到它
2. 主库徽标可见；清除后回退最近使用
3. 单库类型无按钮
4. Dock 与设置页行为一致；写入/清除逻辑有单测
